# Human13 · 로컬 생리 시뮬레이션 워크스페이스

자연어 사건에서 분자·세포·장기 상태와 반응·관측식을 구성하는 로컬 v0.5입니다. 기존 생리 수식과 LLM이 선언한 새 수식을 같은 ODE에서 계산합니다. 새로운 생리 이름마다 소스 코드를 추가할 필요가 없으며, 생성 성공 여부와 검증된 인체 예측 정확도는 구분합니다.

## 실행

이 컴퓨터에는 의존성과 로컬 API 키 설정을 완료했습니다.

```powershell
.\start.ps1
```

[앱 열기](http://localhost:5173/) · [로컬 API 문서](http://127.0.0.1:8000/docs)

`start.ps1 -OpenBrowser`는 브라우저도 엽니다. 실행 중인 Human13은 재사용합니다. `stop.ps1`은 이 시작 스크립트가 기록한 프로세스만 종료합니다. 로그는 `.runtime/`에 있습니다. 포트 충돌 시 다른 프로그램을 종료하지 않고 시작 오류를 보고합니다.

새 환경에서는 Python 3.12, Node.js 22.13 이상 및 uv를 준비합니다.

```powershell
uv venv --python 3.12 .venv
uv pip sync --python .venv\Scripts\python.exe requirements.lock.txt
Copy-Item .env.example .env
cd web
node 'C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js' ci --include=dev --include=optional
cd ..
.\start.ps1
```

Node 설치 위치가 다르면 npm CLI 경로를 바꾸거나 정상적인 환경에서 `npm ci`를 사용합니다. 이 컴퓨터의 npm.cmd 경로 처리 문제를 피하려고 JS 진입점을 직접 호출했습니다. `.env`의 `OPENROUTER_API_KEY`를 설정하세요. 모델 기본값은 요청한 `deepseek/deepseek-v4-flash-0731`입니다.

API 키는 서버의 `.env`에만 있습니다. 프런트엔드 번들·실행 JSON·로그에 포함하지 않습니다. 서버와 화면은 루프백 주소에 바인딩합니다. 로컬 앱이지만 자연어/사건/조회 근거는 OpenRouter에, 물질 이름/구조는 공개 DB에 전송됩니다. 저장된 계획으로 재계산할 때는 이 외부 호출을 반복하지 않습니다.

## v0.4 · FDA QSP 방법론 반영

[2026 FDA QSP 드래프트 대조표](FDA_QSP_ALIGNMENT.md)에 원문 항목, 현재 구현, 남은 근거를 정리했습니다. 문서는 MABEL/최초 인체시험 용량 선정 범위이며, 이 앱에는 모델 구성·평가·보고 방법론을 적용합니다.

- ‘모델 · 검증’에 실행별 질문/사용 목적, 수치 검사, 실측 보정, 독립 검증, 파라미터 근거 장부를 표시합니다. 미수집·미검증 상태를 구분합니다.
- 저장 모델의 계수를 하나씩 변경하고 LLM 연결을 제거해 실제 비교 곡선을 계산합니다. 최대 12개 계수, ±10/20/50%, LLM 추가 호출 없음. 실패와 사라진 출력도 보존합니다.
- 분석 계획·기준 모델·시나리오·검사 결과·소프트웨어 버전/해시를 별도 기록으로 저장합니다. 과거 실행의 소프트웨어 버전을 소급해서 만들지 않습니다.
- 생성 지침에 관련 전체 경로·표적 발현/회전율·수송/대사·종 차이·누락 기전 검토를 반영했습니다. 실측 데이터 보정과 독립 검증은 아직 미실시입니다.

실제 저장된 빛·스트레스 복합 모델에서 생성 계수 6개와 구조 제거를 포함한 14개 시나리오를 새 LLM 호출 없이 계산했습니다. `scripts/smoke_analysis.py`로 저장 모델 재계산과 분석 API를 재확인할 수 있습니다. 새 테스트에는 SGLT1·GLUT2 변화에 따른 혈당 궤적과 보존 장부 검사도 포함됩니다.

## 기존 생리 모듈

설탕의 정량 입력 누락을 고쳤습니다. 자당 분해·SGLT1/GLUT2/GLUT5 수송·인크레틴·인슐린·GLUT4·신장 재흡수가 실제 계산으로 연결됩니다. LLM은 기존 과정을 재사용하거나 제한된 계수와 시간상수를 가진 새 근사 과정을 같은 ODE에 결합합니다. 수송체 기능 조절, LLM 연결 켜기/끄기, 연결 상태와 순간 flux 표시를 추가했습니다. 자세한 수식·출처·한계는 [MODEL_INTEGRATION.md](MODEL_INTEGRATION.md)를 보세요.

## 사용 흐름

1. Human13의 `Event` 입력창에 무엇을 얼마나 언제 했는지 입력합니다. 한국어 입력도 지원하며 화면·생성 설명은 영어로 표시합니다. 화면은 기본 모델 조건을 사용하며 별도의 설정 패널을 표시하지 않습니다.
2. 입력 해석과 분자 조회 후 기존 기전 수식을 계산합니다. 기존 모델에 연결되는 입력은 한 번 계산하고 바로 완료하며, 추가 LLM 검토를 하지 않습니다. 실행 경로가 없는 입력이나 약물의 표적 효과를 구성해야 할 때에만 모델을 생성하고, 그동안 초기 계산을 먼저 표시합니다.
3. `Whole-body response`에서 연결된 전신 관측값 중 변한 항목을 먼저 요약합니다. 주요 6개와 추가 관측값을 구분해 펼칠 수 있습니다. 아래의 `Response pathway`는 입력에서 도달할 수 있고 계산값이 변하는 경로만 하나씩 공개합니다. 같은 상태를 반복 표시하던 관측 노드는 과정 카드의 관측 표시로 합칩니다. 주 연결은 그래프에, 추가 연결과 피드백은 상세 정보에 표시합니다.
4. 노드를 선택하면 시간 곡선, 관련 세포형, 수식, 읽기 전용 파라미터, 분자 정보와 원문 근거를 오른쪽에서 봅니다. Δ는 시작 시점 대비 최대 변화이며 사건이 없는 대조군과의 차이가 아닙니다. 물질량과 농도는 각 노드의 단위로 구분합니다.
5. `Replay reveal`로 노드 공개를 반복하거나 `Reveal all`로 즉시 확인합니다. 모션 감소 설정을 사용하는 환경에서는 바로 전체를 표시합니다. 저장 결과는 주소의 `?run=실행ID`로 다시 열 수 있습니다.

입력 예시: `탄수화물 40g을 먹고 30분 뒤에 6 MET로 30분 운동했어. 물 300mL도 마셨어.` `커피 한 잔`, `잠을 설쳤어`처럼 성분량·강도가 없으면 그 값을 지어내지 않고, 근거와 가정을 명시한 상대 반응 모델을 구성합니다. 수치 경로를 구성하지 못한 입력은 별도 안내로 표시합니다. 노드가 보이지 않는 것이 실제 생리적 영향이 없음을 뜻하지는 않습니다.

`방금 사탕 하나 먹었어`처럼 당 함량이 없는 입력은 원래 섭취량을 `null`로 보존하면서 별도의 **1 g 자당 기준 시나리오**를 실행합니다. 사탕에 자당이 들어 있다는 조건부 가정이며 제품의 실제 조성·크기를 추정하지 않습니다. 알려진 다른 당의 양이 없을 때도 같은 기준량 정책을 사용합니다. 무설탕·당알코올 식품에 자당을 자동 적용하지 않으며, 명시된 영양 질량을 덮어쓰지 않습니다. 계산은 비선형이므로 곡선을 개수나 질량에 비례 확대하면 안 됩니다. 원본 해석·계산용 해석·기준 시나리오를 실행 계획에 각각 기록합니다. 이전 저장 결과는 그대로 보존되므로 수정된 모델을 적용하려면 새로 실행합니다.

영문 표시는 표시용 사본에만 적용합니다. 원문 입력, 수치 궤적, 상태 ID, SMILES, 실행 수식과 저장된 모델 기록은 번역하지 않습니다. 기본 용어는 `backend/locales/en.json`에 보관하며 새로운 설명의 번역은 로컬 캐시에 저장합니다.

기존 모델로 처리되는 사탕·당 섭취·운동 등의 입력은 후속 검토와 중복 수치 계산 없이 완료됩니다. `generation.planning_status=not_needed`는 검토 실패가 아니라 검토가 필요 없었다는 뜻이며 화면에는 별도 검토 문구를 표시하지 않습니다. 기존 모델로 도달하지 못하는 입력과 화합물의 표적 효과에만 LLM 모델 생성을 적용합니다. 약물의 구획 수송만 연결됐다는 사실을 표적 효과까지 모델링했다는 뜻으로 취급하지 않습니다.

새 경로 생성이 필요한 경우 기본 계산의 미리보기는 외부 번역을 기다리지 않고 표시합니다. 작업 단계·경과 시간을 표시하고 서버가 2초 간격으로 상태를 전달합니다. 외부 모델 요청은 생성 90초·일반 텍스트 30초, 최종 영문 표시 준비는 전체 15초로 제한합니다. 생성 실패 시 기본 결과를 유지하고 이유를 표시합니다. 기존 경로가 충분한 경우 명시적 재생성 요청도 불필요한 기전 검토를 실행하지 않으며, 누락 경로의 재생성에는 기존 재시도·캐시 정책을 유지합니다.

## 실제 계산 범위

| 모듈 | 현재 구현 | 근거·경계 |
|---|---|---|
| 분자 식별 | PubChem → RDKit 구조·분자량·SMILES·분자 그림 | 구조만으로 PK/PD를 결정하지 않음 |
| 알려진 표적 | ChEMBL 기전·활성, 장애 시 BindingDB 조회 | BindingDB 유사도 후보는 전체 InChIKey 일치로 재검사. 종·Ki/Kd/IC50/EC50를 분리 표시 |
| 물질 수송 | 입·식도·위·소장·문맥·혈장·조직·제거의 보존 ODE, 반복 투여 공유 | **공통 미보정 파라미터**. 약물별 PBPK/대사/유리 농도/표적 점유율 미구현 |
| 포도당·인슐린·β세포 | 고정한 PMR Topp 2000 CellML의 수식을 파싱해 SciPy로 실행 | 원본 경고: 논문 결과를 재현하지 못함. 원본 수식 일치 검증과 임상 검증은 별개 |
| 영양 | 당 종류별 분해·수송체·문맥·간·내분비 피드백 | 축약 기전 모듈; 전체 장의 Vmax·부피·호르몬 연결 계수는 탐색 가정 |
| 활동 | MET·체중·시간의 에너지 환산 | 활동 중 총 소비량; 개인의 측정 열량이 아님 |
| 순환·열·수분 | 공통 상태에서 심박·박출·저항·열·수분 ODE, MAP 환산 | **미보정 탐색 모델**. MAP는 평균 동맥압이며 수축기 혈압이 아님 |
| LLM 모델 | 임의 상태·구획·산술 속도식·화학양론·다중 사건 피드백·동적 관측 | 기존 상태는 읽기/과정 조절로 결합. 생성 계수와 상대 지수는 탐색 가정 |

노드 상세에서 기존 수식, 정의·단위 환산, 가정 기반 계산, DB 근거와 LLM 근사 과정을 구분합니다. 연결되지 않거나 계산값이 변하지 않는 출력은 메인 그래프에서 숨깁니다. 화면은 탐색 가정을 포함하는 기본 조건을 사용합니다. 세포형 표시는 관련 해상도에 대한 주석이며 개별 세포 전체를 직접 시뮬레이션한 것이 아닙니다.

BindingDB 대체 API는 반환 값에 단위·실험 조건이 없으므로 `API 단위 미제공`으로 표시하고 원문을 보존합니다. Kd와 IC50를 교환하거나 그 값에서 인체 내 결합률을 추정하지 않습니다. 조회는 최대 20개 표본이며 전체 표적 목록을 보장하지 않습니다.

Topp 시뮬레이션의 초기값은 원본 계수에서 유도한 평형 `G=100 mg/dL, I=9.75 µU/mL, β=117 mg`입니다. 원본 파일 초기값 `G=600, I=0, β=0`과 다릅니다. 식사와 운동 연결은 원본의 외부 확장입니다.

새 경로는 `EquationModel` 데이터로 구성하며, 컴파일러가 상태·과정·관측을 등록합니다. 외부 모델 어댑터 자체를 추가할 때는 `process()`·`transfer()`를 직접 사용할 수 있습니다. 공통 혈당·수분 같은 상태를 모듈마다 복제하지 않습니다. LLM은 JSON 수식 선언을 반환하며, 허용된 산술만 해석합니다. Python `eval/exec`는 사용하지 않습니다. 현재 CellML 어댑터는 고정 원본용이며 범용 importer가 아닙니다.

실행 시 원본 해시, 정확한 사건·설정·가정·공유 상태 소유권·과정 ID, DB 근거와 LLM 입출력을 저장합니다. `.env`, 캐시, 실행 기록은 버전 관리에서 제외합니다. UI JSON은 결과·계획·근거를 포함하고 원시 LLM 프롬프트/사용량은 로컬 실행 스냅샷에만 보존합니다. 서버 재실행이 필요하면 실행 중인 서버를 종료하고 `start.ps1`로 시작하세요.

후속 우선순위는 약물별 공개 PBPK/PD 모델 어댑터, 임상 또는 실험 관측 자료로 파라미터 보정, 단위·의미가 맞는 포트 계약 확대, 검증 영역을 가진 근사 모델, 전역 민감도/근거 기반 앙상블 구간입니다. LLM의 새 근사 과정은 수치 실행에 들어가지만, 검증된 모델로 승격하려면 적합 범위·계수 출처·외부 검증이 필요합니다. 현재 곡선을 검증된 일반 인체 예측으로 볼 수는 없습니다.

## 검증

```powershell
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m backend.reference
cd web
node node_modules/typescript/bin/tsc --noEmit
node 'C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js' run build
```

`scripts/smoke_api.py`는 실행 중인 서버에 실제 복합 사건을 보내는 별도 검사입니다. **OpenRouter 호출 비용이 발생**하며 pytest에서 자동 실행하지 않습니다. 저장 계획의 재실행 일치, 엄격 모드, 표적 기록, 질량 보존, 외부 Origin 거부도 확인합니다.

- 85개 핵심/통합 테스트: 기존 생리 수식과 질량 보존에 더해 임의 상태·반응의 생성, 혼합 단위, 다중 사건 피드백, 생성 계수 조절, 무효 수식 차단, 초기 승수, 자동 관측, API 자동 수정·캐시·재계산·강제 재구성·거절된 모델 저장 제외를 확인합니다. 추가로 근거 상태, 국소 민감도, 구조 제거, 비교 불가·실패 보존과 분석 API 저장을 검사합니다. 전신 네트워크의 무입력 평형, 다계통 전파, 영양소 분류, LLM 연결 분리와 빈 모델의 성공 오인 방지도 확인합니다.
- 원본 CellML ↔ SBML/RoadRunner 최대 절대 차이 `6.35e-7` 이하. 비평형 조건도 비교. 파일의 논문 재현 경고를 유지합니다.
- TypeScript 및 프로덕션 빌드 확인. npm.cmd를 쓰는 Sites 빌드 도우미는 이 컴퓨터의 경로 오류로 실패해 같은 프로젝트 build 스크립트를 npm JS 진입점으로 실행했습니다.
- v0.1 당시 실제 API 통합 검사 통과: 요청한 DeepSeek 모델의 해석·경로 생성 2회 호출, 복합 사건 4개, 그래프 40개 노드, 실제 표적 실험 20개, 수치 출력 6개. 저장된 계획의 재계산 곡선이 정확히 같았으며 가정 제외 시 MET 에너지만 남았습니다. 전체 검사 36.11초. 실제 응답 시간과 DB 가용성은 실행마다 달라집니다.
- `start.ps1`로 두 서버를 새로 시작한 후 준비 상태를 확인했습니다. 배포 번들·실행 스냅샷 70개 파일에서 API 키 미포함을 확인했습니다.
